เชื่อมบัญชี Google

สำคัญ: เลือกไฟล์ OAuth JSON ประเภท Desktop app จาก Google Cloud เพียงครั้งเดียว (มี client_id และ client_secret) โปรแกรมเข้ารหัสข้อมูลในเครื่องและเชื่อมอัตโนมัติครั้งต่อไป — เปิด Google Cloud Console ↗

05

ดาวน์โหลด Google Docs เป็น TXT แยกบท

วางลิงก์ Google Docs หนึ่งลิงก์ต่อบรรทัด หรือค้นเอกสารที่แอปเข้าถึงได้ด้วยชื่อ

อ่านจาก Google Docs โดยตรง ไม่แก้เอกสารต้นฉบับ รองรับไฟล์ที่บัญชีนี้มีสิทธิ์อ่าน หากชื่อแท็บสั้น จะอ่านชื่อเต็มจากหัวบทในเนื้อหา

ก่อนใช้งาน Google Docs ครั้งแรก

  1. เปิด Google Cloud Console แล้วสร้างโปรเจกต์
  2. เปิดใช้ Google Docs API และตั้งค่า OAuth consent screen / Google Auth Platform
  3. สร้าง OAuth Client ID ประเภท Desktop app โดยไม่ต้องกำหนด Authorized JavaScript origins
  4. นำ Client ID มาวางด้านบน และใช้บัญชีที่เป็น Test user หากแอปอยู่ในโหมด Testing

Google sign-in จะเปิดเบราว์เซอร์ภายนอกเพื่อยืนยันตัวตน และกลับสู่แอปอัตโนมัติ

ระบบตรวจจับบทอย่างไร?

บทที่ 690 การเดินทางเพื่อการกุศล
เนื้อหานิยาย...
[จบตอน]

บทที่ 691 ล้วนเป็นคนกันเองทั้งนั้น
เนื้อหานิยาย...
[จบบท]

ระบบหาบรรทัดที่เริ่มต้นด้วย บทที่ 690 แล้วเก็บเนื้อหาไปจนถึงก่อนหัวบทถัดไป โดยตรวจว่ามี [จบตอน] หรือ [จบบท] หรือไม่ รวมบรรทัดว่างไว้เพื่อรักษาต้นฉบับ

สิ่งที่ควรรู้

  • TXT รักษาข้อความต้นฉบับทั้งบรรทัดและเครื่องหมายจบ; DOCX ดึงข้อความออกมา แต่รูปภาพ ตารางเชิงโครงสร้าง และรูปแบบตัวอักษรอาจไม่ติดมาด้วย
  • บทซ้ำ, บทไม่มีคำจบ และข้อความก่อนบทแรกจะมีคำเตือนให้ตรวจ
  • หากเลขบทข้าม เช่น 690 → 692 ระบบจะแจ้งบทที่ 691 ว่าอาจขาด ไม่ถือเป็นข้อผิดพลาดบังคับ
  • รายการที่เอาเครื่องหมายถูกออกจะไม่ถูกรวมในไฟล์ส่งออก
  • Google Docs เชื่อมโดย OAuth แค่ช่วงใช้งาน ไม่เก็บ access token ใน localStorage; โหมดเติมบทจะอ่านแท็บเดิม ตรวจเลขบทซ้ำ และไม่เขียนทับเนื้อหาเดิม
